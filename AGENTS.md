# Repository Guidelines

## Project Structure & Module Organization
- `game.ts`: Main TypeScript source (Phaser 3 logic).
- `index.html`: Static entry; loads Phaser from CDN and `dist/game.js`.
- `dist/`: Compiled JS output (`game.js`) generated by TypeScript; do not edit.
- `.github/workflows/deploy.yml`: GitHub Pages build/deploy on pushes to `main`.
- `tsconfig.json`: Compiler settings (`outDir: dist`, CommonJS, DOM libs).
- Tests: add as `*.spec.ts` beside sources or under `__tests__/`.
- Keep runtime logic in `game.ts`; avoid ad‑hoc scripts in `index.html` beyond UI scaffolding.

## Build, Test, and Development Commands
- `npm install`: Install TypeScript and Phaser.
- `npm run build`: Compile `game.ts` to `dist/game.js`.
- `npm run build:watch` or `npm run dev`: Recompile on file changes.
- Local run: open `index.html` in a browser or serve statically (e.g., `npx http-server .`) so `dist/game.js` is loaded.
- `npm test`: Placeholder; configure once tests are added.

## Coding Style & Naming Conventions
- Language: TypeScript (CommonJS). Indent 4 spaces; use semicolons; single quotes.
- Names: `camelCase` for functions/vars, `UPPER_SNAKE_CASE` for constants, `PascalCase` for types/enums.
- Organization: centralize Phaser scene setup in `create`/`update`; keep helpers small and pure.
- Types: prefer explicit types for public helpers; minimize `any` usage.

## Testing Guidelines
- Framework: prefer Vitest or Jest when introduced.
- Test files: name `*.spec.ts`; colocate with sources or use `__tests__/`.
- Scope: unit‑test pure logic (e.g., neighbor counting, pattern detection); avoid Phaser rendering in unit tests.
- Run: `npm test` (after setup); keep tests fast and deterministic.

## Commit & Pull Request Guidelines
- Commits: follow Conventional Commits (e.g., `feat: change cell color`, `fix: bounds check`); imperative mood; English or Japanese accepted.
- PRs: include a clear description, linked issues, and before/after screenshots or short clips for visual changes; keep focused and small; update `README.md` when behavior or controls change.

## CI/CD & Deployment
- Pushes to `main` trigger GitHub Actions to build and deploy to Pages.
- Workflow expects `npm run build` to produce `dist/game.js`; it copies assets into `docs/` and cache‑busts the script tag.
- Pin external CDNs (Phaser version) and avoid inline scripts to keep CSP simple.
